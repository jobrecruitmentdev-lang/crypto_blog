> ## ⚠️ PIVOT UPDATE
> Scope changed: the site is now blog-first. Content (posts) is authored and
> managed in **Strapi** (self-hosted headless CMS) instead of a custom
> scraper/adapter backend. The Next.js frontend fetches blog content from
> Strapi's REST/GraphQL API. The airdrop-directory pages/components already
> built stay as-is on mock data for now, but the custom Postgres/adapter/
> ingestion backend described further down and in `backend-plan.md` is
> **superseded** — see the rewritten `backend-plan.md` for the current
> Strapi-based architecture. Sections below (Backend APIs, Admin Panel) are
> kept for historical reference but are annotated where Strapi now replaces
> them.

This is actually a **very strong architecture to replicate**, but I would **not** clone it 1:1. I would build a **modern version** using Next.js, Tailwind CSS, GSAP, Magic UI, React Bits, and a component-based architecture while keeping the same SEO strengths.

### One Improvement Over the Reference Site

The current site is visually effective but still follows a fairly traditional content layout. For a new implementation, I'd make the homepage **data-driven and personalized**:

* Dynamic "Trending Now" based on user activity.
* AI-powered related project recommendations.
* Advanced filtering without page reloads.
* Better mobile navigation with bottom actions.
* Rich schema on every listing.
* Progressive Web App (PWA) support with offline caching for recently viewed pages.

This preserves the SEO strengths of the reference while providing a more modern user experience and a cleaner architecture for long-term maintenance.
